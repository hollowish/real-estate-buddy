A.1 Create Cognito User Pool ⏱ 2 hrs
Set up the AWS service that handles all user accounts — passwords, email verification, and MFA for HomeScore AI.
▼
What / Why / How
What is it?

A Cognito User Pool is AWS's managed user database. It stores all user accounts, handles password hashing, and sends verification emails — you never touch raw passwords.

Why do we need it?

HomeScore AI needs users to sign up and log in. Instead of building our own auth server (complex + risky), we use Cognito — AWS handles the hard security stuff.

Where to do it?

100% in the AWS Console. No code needed for this task. Takes about 10 minutes to click through.

Step-by-step (AWS Console)
  1. Go to AWS Console → search "Cognito" → Click "Create user pool"
  2. Step 1 — Sign-in: Select Email as the sign-in option. Click Next.
  3. Step 2 — Security: Keep password policy, change minimum length to 8. Check: uppercase, number, special character required.
  4. Step 2 — MFA: Select "Require MFA" → choose Authenticator app (TOTP). This is the QR code your signup page will show.
  5. Step 3 — Sign-up: Keep self-registration ON. Email verification: "Send email with code".
  6. Step 4 — Message delivery: Use Cognito's built-in email (fine for demo).
  7. Step 5 — App client: Name it homescore-web-client. ⚠️ UNCHECK "Generate client secret" — browser apps can't use secrets.
  8. Step 5 — Auth flows: Make sure USER_PASSWORD_AUTH is checked.
  9. Review and Create user pool. Note down the User Pool ID and App Client ID.
⚠️ Save these two values! You'll need them in almost every other task: User Pool ID (format: us-east-1_Xxxxxxxx) and App Client ID (long string of letters/numbers).
Done when:
  • User Pool exists in AWS Console
  • Email as username ✓
  • Password policy: 8+ chars, uppercase, number, special char ✓
  • TOTP MFA enabled and required ✓
  • App Client with no secret, USER_PASSWORD_AUTH flow ✓

A.3Build Signup Page⏱ 3 hrs
React form: email + password + confirm password → calls Cognito signUp → shows email verification → shows MFA setup QR code.
▼
The 3 screens your signup page needs
Screen 1

Email + password form. User fills it out and hits "Sign Up". You call Cognito's signUp function.

Screen 2

Email verification. Cognito sends a 6-digit code to the user's email. They type it in to confirm their account.

Screen 3

MFA Setup. After email confirmed, show a QR code from Cognito. User scans with Google Authenticator app.

Full React Component — src/pages/SignupPage.jsx
JSX — src/pages/SignupPage.jsx
import { useState } from 'react';
import {
  signUp,
  confirmSignUp,
  signIn,
  setUpTOTP,
  verifyTOTPSetup,
} from 'aws-amplify/auth';

// Step 1: Show signup form
// Step 2: Show email verification code input
// Step 3: Show MFA QR code setup
export default function SignupPage() {
  const [step, setStep] = useState(1);
  const [email, setEmail] = useState('');
  const [password, setPassword] = useState('');
  const [confirm, setConfirm] = useState('');
  const [code, setCode] = useState('');
  const [qrCode, setQrCode] = useState('');
  const [totpCode, setTotpCode] = useState('');
  const [error, setError] = useState('');
  const [loading, setLoading] = useState(false);

  // ── SCREEN 1: Handle Signup ──
  const handleSignup = async () => {
    if (password !== confirm) { setError('Passwords do not match'); return; }
    setError(''); setLoading(true);
    try {
      await signUp({
        username: email,
        password,
        options: { userAttributes: { email } }
      });
      setStep(2); // → show email verification screen
    } catch (err) {
      setError(err.message);
    } finally { setLoading(false); }
  };

  // ── SCREEN 2: Confirm Email Code ──
  const handleConfirmEmail = async () => {
    setError(''); setLoading(true);
    try {
      await confirmSignUp({ username: email, confirmationCode: code });
      // After email confirmed, sign in silently to set up MFA
      await signIn({ username: email, password });
      // Get the QR code URI for the authenticator app
      const totpSetup = await setUpTOTP();
      setQrCode(totpSetup.getSetupUri('HomeScore AI', email).toString());
      setStep(3); // → show MFA QR code screen
    } catch (err) {
      setError(err.message);
    } finally { setLoading(false); }
  };

  // ── SCREEN 3: Verify MFA Setup ──
  const handleVerifyMFA = async () => {
    setError(''); setLoading(true);
    try {
      await verifyTOTPSetup({ code: totpCode });
      // MFA is now set up! Redirect to login page.
      window.location.href = '/login';
    } catch (err) {
      setError(err.message);
    } finally { setLoading(false); }
  };

  return (
    <div>
      {error && <p style={{color:'red'}}>{error}</p>}

      {/* ── SCREEN 1 ── */}
      {step === 1 && (
        <div>
          <h2>Create Account</h2>
          <input placeholder="Email" value={email} onChange={e => setEmail(e.target.value)} />
          <input type="password" placeholder="Password" value={password} onChange={e => setPassword(e.target.value)} />
          <input type="password" placeholder="Confirm Password" value={confirm} onChange={e => setConfirm(e.target.value)} />
          <button onClick={handleSignup} disabled={loading}>{loading ? 'Creating...' : 'Sign Up'}</button>
        </div>
      )}

      {/* ── SCREEN 2: Email Code ── */}
      {step === 2 && (
        <div>
          <h2>Check Your Email</h2>
          <p>We sent a 6-digit code to {email}</p>
          <input placeholder="Enter code" value={code} onChange={e => setCode(e.target.value)} />
          <button onClick={handleConfirmEmail} disabled={loading}>Verify Email</button>
        </div>
      )}

      {/* ── SCREEN 3: MFA QR Code ── */}
      {step === 3 && (
        <div>
          <h2>Set Up Authenticator App</h2>
          <p>Scan this QR code with Google Authenticator or Authy</p>
          {/* Use a QR code library to display qrCode URI */}
          <img src={`https://api.qrserver.com/v1/create-qr-code/?size=200x200&data=` + encodeURIComponent(qrCode)} alt="MFA QR Code" />
          <p>Then enter the 6-digit code from the app:</p>
          <input placeholder="Code from app" value={totpCode} onChange={e => setTotpCode(e.target.value)} />
          <button onClick={handleVerifyMFA} disabled={loading}>Finish Setup</button>
        </div>
      )}
    </div>
  );
}
💡 Tip: The styling here is minimal on purpose. Apply your team's CSS/Tailwind on top. Focus on making the logic work first, then style it.
Done when:
  • Signup form with email, password, confirm password ✓
  • Email verification code screen shows after signup ✓
  • MFA QR code shows after email verified ✓
  • User can scan QR with Google Authenticator ✓
A.4Build Login Page⏱ 3 hrs
React form: email + password + MFA code (2 steps). Stores JWT tokens in memory. On success, redirects to dashboard.
▼
How login with MFA works
  1. User enters email + password → you call signIn(). Cognito checks credentials.
  2. Cognito returns a challenge: "I need the MFA code too." Your app shows a second input field.
  3. User opens Google Authenticator, gets the current 6-digit code, types it in.
  4. You call confirmSignIn() with the MFA code → Cognito returns the JWT tokens.
  5. Store tokens in memory (a simple JS variable or React state/context) → redirect to home.
Full React Component — src/pages/LoginPage.jsx
JSX — src/pages/LoginPage.jsx
import { useState } from 'react';
import { signIn, confirmSignIn } from 'aws-amplify/auth';
import { useAuth } from '../context/AuthContext'; // we'll create this in A.5

export default function LoginPage() {
  const [step, setStep] = useState('credentials'); // 'credentials' or 'mfa'
  const [email, setEmail] = useState('');
  const [password, setPassword] = useState('');
  const [mfaCode, setMfaCode] = useState('');
  const [error, setError] = useState('');
  const [loading, setLoading] = useState(false);
  const { login } = useAuth(); // function to save token to context

  // ── Step 1: Email + Password ──
  const handleCredentials = async () => {
    setError(''); setLoading(true);
    try {
      const result = await signIn({ username: email, password });
      // Check if Cognito is asking for MFA code
      if (result.nextStep.signInStep === 'CONFIRM_SIGN_IN_WITH_TOTP_CODE') {
        setStep('mfa'); // → show MFA input screen
      }
    } catch (err) {
      setError(err.message);
    } finally { setLoading(false); }
  };

  // ── Step 2: MFA Code ──
  const handleMFA = async () => {
    setError(''); setLoading(true);
    try {
      const result = await confirmSignIn({ challengeResponse: mfaCode });
      if (result.isSignedIn) {
        // Login succeeded! Save token and redirect.
        await login(); // fetchAuthSession inside AuthContext
        window.location.href = '/';
      }
    } catch (err) {
      setError(err.message);
    } finally { setLoading(false); }
  };

  return (
    <div>
      {error && <p style={{color:'red'}}>{error}</p>}

      {step === 'credentials' && (
        <div>
          <h2>Log In</h2>
          <input placeholder="Email" value={email} onChange={e => setEmail(e.target.value)} />
          <input type="password" placeholder="Password" value={password} onChange={e => setPassword(e.target.value)} />
          <button onClick={handleCredentials} disabled={loading}>
            {loading ? 'Checking...' : 'Log In'}
          </button>
        </div>
      )}

      {step === 'mfa' && (
        <div>
          <h2>Enter Authenticator Code</h2>
          <p>Open Google Authenticator and enter the 6-digit code for HomeScore AI</p>
          <input placeholder="6-digit code" value={mfaCode} onChange={e => setMfaCode(e.target.value)} maxLength=6 />
          <button onClick={handleMFA} disabled={loading}>Verify</button>
        </div>
      )}
    </div>
  );
}
Done when:
  • Email + password form works ✓
  • After correct password, MFA code screen appears ✓
  • After correct MFA code, user is logged in ✓
  • JWT stored in memory (context), NOT localStorage ✓
A.5Build Logout + Auth Context⏱ 30 min
Create the AuthContext that stores the token in memory, and a logout function that clears it.
▼
AuthContext — the "memory" for your token

React Context is like a global variable your whole app can read. You store the token here instead of localStorage — it disappears when the tab closes, which is more secure.

JSX — src/context/AuthContext.jsx
import { createContext, useContext, useState, useEffect } from 'react';
import { signOut, fetchAuthSession, getCurrentUser } from 'aws-amplify/auth';

const AuthContext = createContext(null);

export function AuthProvider({ children }) {
  const [token, setToken] = useState(null);    // JWT stored in memory only
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true); // checking if already logged in

  // On app load: check if Amplify still has a valid session
  useEffect(() => {
    checkSession();
  }, []);

  const checkSession = async () => {
    try {
      const session = await fetchAuthSession();
      const currentUser = await getCurrentUser();
      setToken(session.tokens?.accessToken?.toString());
      setUser(currentUser);
    } catch {
      // Not logged in, that's fine
    } finally { setLoading(false); }
  };

  // Call this after confirmSignIn() in LoginPage
  const login = async () => {
    await checkSession();
  };

  // Call this from logout button anywhere in the app
  const logout = async () => {
    await signOut();
    setToken(null);    // clear from memory
    setUser(null);
    window.location.href = '/login';
  };

  return (
    <AuthContext.Provider value={{ token, user, login, logout, loading }}>
      {children}
    </AuthContext.Provider>
  );
}

// Custom hook — use this in any component: const { token, logout } = useAuth()
export const useAuth = () => useContext(AuthContext);
💡 Wrap your whole app with this. In your src/main.jsx, wrap <App /> with <AuthProvider><App /></AuthProvider>.

A.6Create ProtectedRoute Component⏱ 1 hr
A wrapper that checks if the user is logged in. If not, kicks them to /login. Share with your whole team.
▼
What it does in plain English

Think of ProtectedRoute like a bouncer at a door. Any page wrapped in it will first check: "does this user have a valid token?" If yes, let them in. If no, send them to /login immediately. Your teammates wrap their pages with this — they don't need to write auth checks themselves.

JSX — src/components/ProtectedRoute.jsx (share with team!)
import { Navigate } from 'react-router-dom';
import { useAuth } from '../context/AuthContext';

/**
 * Wrap any page with this to require login.
 * Usage: <ProtectedRoute><DashboardPage /></ProtectedRoute>
 */
export default function ProtectedRoute({ children }) {
  const { token, loading } = useAuth();

  // Still checking if user is logged in — show nothing yet
  if (loading) return <div>Loading...</div>;

  // No token = not logged in → redirect to login page
  if (!token) return <Navigate to="/login" replace />;

  // Has token = logged in → show the page
  return children;
}

// ── How your teammates use it (in App.jsx routes) ──
// <Route path="/dashboard" element={
//   <ProtectedRoute><DashboardPage /></ProtectedRoute>
// } />
🔐 Security note for your demo: This is "frontend protection" — it stops regular users from accidentally visiting protected pages. The REAL security is API Gateway rejecting requests with invalid tokens on the backend. Both layers matter.

A.7Create Lambda: reb-auth-handler⏱ 3 hrs
A serverless function that handles create/get/update profile. Gets the userId from the JWT — NOT from the request body.
▼
What is Lambda?

A Lambda is a small function that runs on AWS when called. No server to manage — AWS runs it only when your API is called. Cheaper and simpler for class projects.

Why userId from token?

If userId came from the request body, a hacker could type anyone's userId and read their profile. The token can't be faked — it's cryptographically signed by AWS.

Where to create it?

AWS Console → Lambda → Create function. Runtime: Node.js 20. Paste the code below into the inline editor.

Lambda Code — paste into AWS Lambda inline editor
JavaScript — Lambda Function (Node.js 20)
import { DynamoDBClient } from '@aws-sdk/client-dynamodb';
import { DynamoDBDocumentClient, GetCommand, PutCommand, UpdateCommand } from '@aws-sdk/lib-dynamodb';

const client = new DynamoDBClient({});
const db = DynamoDBDocumentClient.from(client);
const TABLE = 'reb-users';

export const handler = async (event) => {
  // ── Get userId from JWT claims (NOT from request body) ──
  // API Gateway puts the decoded token claims in requestContext.authorizer.jwt.claims
  const userId = event.requestContext?.authorizer?.jwt?.claims?.sub;

  if (!userId) {
    return response(401, { error: 'Unauthorized — no user id in token' });
  }

  const method = event.requestContext.http.method;
  const body = event.body ? JSON.parse(event.body) : {};

  try {
    // ── GET /api/auth/profile ──
    if (method === 'GET') {
      const result = await db.send(new GetCommand({ TableName: TABLE, Key: { userId } }));
      if (!result.Item) return response(404, { error: 'Profile not found' });
      return response(200, result.Item);
    }

    // ── POST /api/auth/profile (create) ──
    if (method === 'POST') {
      const profile = {
        userId,                                          // from JWT — cannot be spoofed
        displayName: body.displayName || '',
        email: body.email || '',
        preferences: body.preferences || {},
        createdAt: new Date().toISOString(),
      };
      await db.send(new PutCommand({ TableName: TABLE, Item: profile }));
      return response(201, { message: 'Profile created', profile });
    }

    // ── PUT /api/auth/profile (update) ──
    if (method === 'PUT') {
      await db.send(new UpdateCommand({
        TableName: TABLE,
        Key: { userId },
        UpdateExpression: 'SET displayName = :n, preferences = :p, updatedAt = :u',
        ExpressionAttributeValues: {
          ':n': body.displayName,
          ':p': body.preferences || {},
          ':u': new Date().toISOString(),
        },
      }));
      return response(200, { message: 'Profile updated' });
    }

    return response(405, { error: 'Method not allowed' });

  } catch (err) {
    console.error(err);
    return response(500, { error: 'Internal server error' });
  }
};

// Helper: format the HTTP response
function response(statusCode, body) {
  return {
    statusCode,
    headers: { 'Content-Type': 'application/json', 'Access-Control-Allow-Origin': '*' },
    body: JSON.stringify(body),
  };
}
🔐 Key security concept — IDOR prevention: Notice how userId comes from event.requestContext.authorizer.jwt.claims.sub — NOT from the request body. If it came from the body, User A could type User B's ID and read their data. This is called an IDOR vulnerability (Insecure Direct Object Reference). Your demo should explain this!
Done when:
  • Lambda named reb-auth-handler exists in AWS ✓
  • Handles POST, GET, PUT on /api/auth/profile ✓
  • userId read from JWT claims — never from request body ✓

A.9Create IAM Role for Lambda⏱ 1 hr
Give the Lambda permission to read/write reb-users ONLY. No other permissions. Classic least-privilege.
▼
Step-by-step (AWS Console)
  1. Go to IAM → Policies → Create Policy → JSON tab
  2. Paste the policy below. Replace YOUR_REGION and YOUR_ACCOUNT_ID.
  3. Name it RebAuthLambdaPolicy. Create it.
  4. Go to IAM → Roles → Create Role
  5. Trusted entity: AWS Service → Lambda
  6. Attach policies: find and check RebAuthLambdaPolicy + AWSLambdaBasicExecutionRole (for CloudWatch logs)
  7. Name the role RebAuthLambdaRole. Create it.
  8. Back in your Lambda → Configuration → Permissions → change execution role to RebAuthLambdaRole
JSON — IAM Policy (paste into JSON editor)
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DynamoDBRebUsersOnly",
      "Effect": "Allow",
      "Action": [
        "dynamodb:GetItem",
        "dynamodb:PutItem",
        "dynamodb:UpdateItem"
      ],
      "Resource": "arn:aws:dynamodb:YOUR_REGION:YOUR_ACCOUNT_ID:table/reb-users"
    }
  ]
}
🔐 Least-privilege in action: This Lambda can ONLY touch the reb-users table. It can't delete tables, access S3, call other services, or do anything else. If this Lambda gets exploited, the damage is contained. This is a key security concept to demo!

Full React Component — src/pages/ProfilePage.jsx

import { useState, useEffect } from 'react';
import { useAuth } from '../context/AuthContext';

const API = 'https://YOUR_API_GATEWAY_ID.execute-api.us-east-1.amazonaws.com/dev';

export default function ProfilePage() {
  const { token } = useAuth();
  const [displayName, setDisplayName] = useState('');
  const [preferences, setPreferences] = useState({
    mustHaves: '',       // e.g. "3 bedrooms, garage, good schools"
    dealBreakers: '',   // e.g. "busy road, no yard"
    preferredAreas: '', // e.g. "San Francisco, Oakland"
    budgetMin: '',
    budgetMax: '',
  });
  const [saved, setSaved] = useState(false);
  const [loading, setLoading] = useState(false);

  // Load existing profile on page load
  useEffect(() => {
    loadProfile();
  }, []);

  const loadProfile = async () => {
    try {
      const res = await fetch(`${API}/api/auth/profile`, {
        headers: { 'Authorization': `Bearer ${token}` }  // JWT sent in header
      });
      if (res.ok) {
        const data = await res.json();
        setDisplayName(data.displayName || '');
        setPreferences(data.preferences || preferences);
      }
    } catch (err) { console.error(err); }
  };

  const saveProfile = async () => {
    setLoading(true);
    try {
      const res = await fetch(`${API}/api/auth/profile`, {
        method: 'PUT',
        headers: {
          'Authorization': `Bearer ${token}`,
          'Content-Type': 'application/json',
        },
        body: JSON.stringify({ displayName, preferences }),
      });
      if (res.ok) setSaved(true);
    } catch (err) { console.error(err); }
    finally { setLoading(false); }
  };

  return (
    <div>
      <h2>Your Profile & Preferences</h2>
      {saved && <p style={{color:'green'}}>✓ Saved!</p>}

      <label>Display Name</label>
      <input value={displayName} onChange={e => setDisplayName(e.target.value)} />

      <h3>Home Preferences</h3>

      <label>Must-Haves (e.g. 3 bedrooms, good schools)</label>
      <textarea value={preferences.mustHaves}
        onChange={e => setPreferences({...preferences, mustHaves: e.target.value})} />

      <label>Deal-Breakers (e.g. busy road, flood zone)</label>
      <textarea value={preferences.dealBreakers}
        onChange={e => setPreferences({...preferences, dealBreakers: e.target.value})} />

      <label>Preferred Areas</label>
      <input value={preferences.preferredAreas}
        onChange={e => setPreferences({...preferences, preferredAreas: e.target.value})} />

      <label>Budget Range</label>
      <input placeholder="Min $" value={preferences.budgetMin}
        onChange={e => setPreferences({...preferences, budgetMin: e.target.value})} />
      <input placeholder="Max $" value={preferences.budgetMax}
        onChange={e => setPreferences({...preferences, budgetMax: e.target.value})} />

      <button onClick={saveProfile} disabled={loading}>
        {loading ? 'Saving...' : 'Save Preferences'}
      </button>
    </div>
  );
}

Key Security Concepts to Demo

Your team leader specifically listed these. Here's exactly what to say and show for each one:

🔒 How Cognito handles passwords

What to say: "We never see or store user passwords. When a user signs up, Cognito hashes the password using SRP (Secure Remote Password protocol). We only call signUp() — the password goes directly to AWS over HTTPS, never touches our code or database."

Show: Your DynamoDB reb-users table — notice there's no password field.

🎟️ How JWT tokens work

What to say: "After login, Cognito gives us a JWT — a signed token with 3 parts: header, payload, signature. The payload contains claims like the user's ID (sub), email, and token expiry. The signature proves AWS issued it."

Show: Copy the token from your app → paste into jwt.io → point to the sub, email, exp fields.

🛡️ userId from token, not body (IDOR)

What to say: "In our Lambda, we get the userId from the JWT claims — not the request body. If we used the request body, I could type someone else's userId and read their private home preferences. This is called an IDOR attack. JWT claims can't be faked because they're cryptographically signed."

Show: Point to line in Lambda: event.requestContext.authorizer.jwt.claims.sub.

⛔ Expired token rejection

What to say: "API Gateway validates every token before it reaches our Lambda. If the token is expired, modified, or fake, API Gateway returns 401 immediately — our Lambda never even runs."

Show: In Postman or browser, make a request with no Authorization header → show the 401 response. Then add a valid token → show 200.
